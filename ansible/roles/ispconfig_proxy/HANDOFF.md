## Before the first run on the VPS

Three things, by hand, in this order:

1. **Move the two secrets.** `group_vars/vps/vars.yml` reads
   `vault_ispconfig_proxy_username` and `vault_ispconfig_proxy_password`. They
   are still `vault_wireguard_ispconfig_username` and `..._password` in
   `group_vars/homelab/vault`, which the VPS does not see. This rework could not
   edit the vaults (the session's permission mode refused the re-encryption),
   so:

   ```
   cd ansible
   ansible-vault view group_vars/homelab/vault | grep wireguard_ispconfig
   ansible-vault edit group_vars/vps/vault      # add both, under the new names
   ansible-vault edit group_vars/homelab/vault  # remove both
   ```

2. **Delete the six extra sites in the panel.** The VPS has one site per
   external service today. `mealie.cindergla.de` stays and becomes the site;
   `argocd`, `auth`, `todo`, `memories`, `copperforge` and `vorleser` must go
   before the role can add them as alias domains. The role refuses to run while
   they exist and names them. Expect a short outage for those six until the role
   has run and ISPConfig has re-issued the certificate.

3. **Run it and look.** `ansible-playbook site.yml --tags ispconfig_proxy -v`,
   then open the mealie site in the panel: six alias domains, Let's Encrypt on,
   the directives with `https://10.0.0.2/`. A second run must report no change.

## Do not rediscover these

- The API **answers HTTP 200 to everything**; the error is in `json.code`.
- `sites_web_domain_update` **merges with the old record** but **resets empty
  `pm_*` fields to its defaults** first. Send the full parameter set.
- `sites_web_aliasdomain_add` **needs `type: alias`** in the params; the form's
  own default is not a type.
- **The domain column is unique across sites and aliases.** Look a name up
  before adding it, or the error says nothing useful.
- `ansible-lint` treats **every YAML under `molecule/` as a playbook** unless it
  sits in a `tasks/` directory. Shared task files go in
  `molecule/resources/tasks/`.
- `ansible-lint --offline .` reports two failures. None is a defect; see the
  "Linting" section of `CLAUDE.md`.

## Running the tests

```
mise run fast                    # local + default, about 2 minutes
mise run scenario update         # the named ones
mise run full                    # all four, about 5 minutes
```

`molecule test -s local` alone takes seconds and needs no container.

The Docker scenarios need Docker and nothing else: the stub is a Python script
in `molecule/resources/files/`, started by `prepare.yml` inside the container.
