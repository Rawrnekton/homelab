## Where it stands

The role is feature-complete for v1.0.0. All 21 variables in
`meta/argument_specs.yml` change the state of the node, Cilium included.

## Cilium, as it was built

- `tasks/cilium.yml` runs on the bootstrap node **between** the bootstrap and
  the join, so the CNI is up before any other node arrives.
- It renders `templates/cilium.yaml.j2` into
  `/var/lib/rancher/k3s/server/manifests/cilium.yaml`. The CR carries
  `bootstrap: true`, which is what lets helm-controller run its install job
  before the cluster has a network.
- It waits for the Cilium DaemonSet, then touches `cilium.yaml.skip`. From
  that moment k3s treats the manifest as if it were not there, and a GitOps
  tool can own the chart. **Never delete the HelmChart resource** —
  helm-controller answers that with `helm delete` and the CNI goes away.
  Deleting or skipping the FILE removes nothing.
- `tasks/verify.yml` now waits for every node to report Ready.

## Do not rediscover these

- `/readyz` answers **401**. k3s turns anonymous authentication off. Only
  `/ping` and `/cacerts` are open, and `/ping` says nothing about the API being
  ready. Use `k3s kubectl get --raw /readyz`.
- `delegate_to` is templated **before** `when` is evaluated. A task that
  delegates to `k3s_first_control_node` must sit behind `include_tasks`, not
  `import_tasks`, or it breaks the `k3s_state: absent` path.
- A block in `handlers/` takes neither a name nor a `listen`, so a handler that
  needs two steps is two tasks on one `listen` topic.
- `throttle: 1` does not give a strict rolling restart. Ansible's linear
  strategy finishes a task on every host before it starts the next one.
- A retry loop (`until`) that runs out of attempts fails the task even with
  `failed_when: false`. Put `ignore_errors: true` on it when an assert behind
  it carries the real message.
- The molecule image declares `/sys/fs/cgroup` as a `VOLUME`. With
  `cgroupns_mode: private` and no bind mount over it, systemd gets an ext4
  volume and the container dies with exit 255 and an empty log. The `cilium`
  scenario mounts cgroup2 in its entry point, the way kind does.
- `ansible-lint --offline .` reports four failures. None is a defect; see the
  "Linting" section of `CLAUDE.md` for what each one is.

## Running the tests

```
mise run fast                  # local + default, about 2 minutes
mise run scenario ha cluster   # the named ones
mise run full                  # all ten
```

Everything goes through `scripts/molecule-tally.sh`, which keeps going when a
scenario fails and prints a table at the end.

`molecule test -s local` alone takes 23 seconds and needs no container. Use it
for anything about the input contract, about what `config.yaml.j2` renders, or
about the HelmChart CR.

`mise run scenario cilium` is the only scenario that depends on the kernel of
the host: it needs bpffs mounted and shared at `/sys/fs/bpf`, cgroup v2 and a
kernel of 5.14 or later. Its `molecule.yml` header says why.
